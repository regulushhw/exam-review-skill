# 实战经验

从已做过的复习资料里记下的坑。现象、原因、解决办法都保持原记录。新坑追加在对应类别下，并按仓库 `README.md` 抬高版本号。

文中「写入文件」指用当前环境的写文件能力把内容保存到指定路径，不是只把内容打在回复里。

## LaTeX / 公式类

**0. Python 普通字符串中的 `\b` 被解释为退格符**

- 现象：`$\bar{w}$` 渲染失败，控制台看到 `\x08ar`
- 解决：所有含 LaTeX 的字符串用 `r"..."` 双引号 raw string

**1. Python f-string 吞掉 LaTeX 反斜杠**

- 影响：`\vec` → `\x0bec`，`\alpha` → `\x07lpha`
- 解决：永远用 `r"..."` raw string，禁止用 f-string 拼接 LaTeX

**2. raw string 单引号 vs 双引号陷阱**

- 现象：`r'$K'$'` 语法错误（LaTeX 撇号截断字符串）
- 解决：统一用 `r"..."` 双引号 raw string

**3. JSON 是 LaTeX 内容的最佳载体**

- 做法：含 LaTeX 的数据存 JSON → `scripts/assemble.py` 读取 JSON 拼装 HTML
- 好处：JSON 里 `$LaTeX$` 是纯文本，不存在转义问题
- 结构见 [`architecture.md`](architecture.md)。不要为当前课程再写一个拼装脚本（v5.1）

**4. PDF 提取的 LaTeX 公式是垃圾**

- 现象：提取出来是 `x=3t-5t3+6` 而不是 `$x = 3t - 5t^3 + 6$`
- 解决：质量差就根据知识点从零编写，别硬翻译

**5. MathJax 配置不当导致公式小/模糊**

- 解决：配 `svg: { scale: 1.05 }`，CSS 加 `mjx-container { font-size: 105% }`
- 行高：`line-height: 2.2`，否则公式上下被截断

**6. 有 LaTeX 公式但没加载 MathJax 脚本**

- 现象：公式显示成纯文本
- 解决：生成后立即检查 `<head>` 里是否有 MathJax 配置和加载脚本

## 文件提取类

**1. PDF 提取质量差**

- 解决：pdfplumber → OCR → 视觉模型，逐步升级
- 预防：`scripts/extract_and_check.py` 自动检查字符数，< 500 字符自动标记（v5.1，不要另写提取脚本）
- 决策树见 [`vision-workflow.md`](vision-workflow.md)

**2. 旧版 .doc 读不了**

- 解决：提前手动转 .docx（WPS / LibreOffice）

**3. pandoc 不支持 PDF 输入**

- 解决：PDF 用 pdfplumber，doc/docx 用 pandoc

**4. 中文引号导致路径解析失败**

- 解决：重命名文件，去掉特殊字符

**5. PPT 转 PDF 几乎一定是图片型**

- 解决：直接走视觉分析，跳过 pdfplumber

**6. 视觉分析页面需分批处理**

- 解决：每批 4–5 张图片，避免超出工具限制

## HTML 生成类

**1. CSS 类名不匹配**

- 解决：`<style>` 里定义和 HTML 引用要一致

**2. 多次编辑同一文件导致内容覆盖**

- 解决：每次编辑前先读完整文件，用精确的原文片段替换，避免整文件覆盖

**3. Windows 控制台编码问题**

- 现象：`print()` 输出中文 / emoji 乱码
- 解决：调试信息写文件（UTF-8），不用 `print()` 打到控制台
- 预防：Python 脚本中禁用 emoji，所有非 ASCII 输出写文件

**4. Bash heredoc 与 Python 单引号冲突**

- 解决：长脚本直接写成 `.py` 文件，别用 heredoc

**5. 练习题答案直接暴露**

- 解决：答案默认 `display:none`，用 JS 切换显示
- 每章加「显示全部 / 隐藏全部」批量按钮

**6. 答案按钮 JS bug（nextElementSibling 找不到元素）**

- 解决：`onclick="this.parentElement.nextElementSibling..."`

**7. 全量重写风险大**

- 解决：局部替换，用 div 嵌套深度计数器定位匹配闭合标签（`scripts/assemble.py --patch`，代码见 [`architecture.md`](architecture.md)）

## 文件管理类

**1. 生成太多文件**

- 解决：提前说好文件数量

**2. 忘记删除临时文件**

- 解决：生成完立即用 `scripts/cleanup.py` 删除 `extracted/`、`pdf_images/`、临时脚本（v5.1）

**3. 文件命名不规范**

- 解决：统一用下划线或短横线

**4. 视觉分析中间图片未清理**

- 解决：HTML 生成完立即删除 `pdf_images/`

**5. 沙箱路径限制（v5.0 新增）**

- 现象：直接写桌面路径被阻止，文件保存失败
- 原因：沙箱安全策略限制写入用户目录（桌面 / 文档 / Downloads）
- 解决：先写工作区，再按当前环境交付文件的方式交给用户
- 预防：涉及用户目录的操作，路径统一用工作区相对路径

## 任务管理类

**1. 误报任务状态**

- 解决：更新任务状态前，先检查实际完成情况

**2. 没有先计划就执行**

- 解决：先输出计划，批准后再动手

**3. 任务拆分不够细**

- 解决：每个任务不超过 30 分钟，超时就拆分

**4. 没有主动建议视觉分析**

- 现象：PDF 提取质量差，AI 继续用领域知识补充
- 解决：提取质量差立即建议切换方法

**5. Agent 输出没保存文件（v5.0 新增）**

- 现象：Agent 说「已完成」，但磁盘上找不到文件
- 原因：任务指令没有明确要求把结果写入文件，Agent 容易只在回复文本里输出内容
- 解决：指令中必须明确写「生成完毕后，把结果写入文件：XXX；保存成功后回复『XX 已保存』」
- 预防：检查所有子任务指令，确保每条都有明确的保存路径
- 模板见 [`../templates/agent-task-template.md`](../templates/agent-task-template.md)

**6. 多 Agent 结果收集混乱（v5.0 新增）**

- 现象：多个 Agent 同时完成，内容散在各条回复里，难以汇总
- 原因：输出留在各自的回复文本中，没有统一落盘
- 解决：每个 Agent 负责保存一个独立文件，主脚本读取这些文件组装最终输出
- 预防：多 Agent 任务设计成「每 Agent 保存一个文件」，而不是「每 Agent 返回内容」

## 内容质量类

**1. 没有先验证提取质量就承诺内容**

- 解决：提取完立即抽查，质量差马上换方法

**2. 没有验证生成的例题是否正确**

- 解决：每道例题人工核对

**3. 练习题难度没有分级**

- 解决：标注难度（⭐～⭐⭐⭐⭐），从易到难排列

**4. 从乱码 PDF 拼凑练习题**

- 解决：果断放弃乱码结果，根据知识点直接出题

**5. 用通用领域知识代替真实课件内容**

- 现象：PDF 提取失败后，用通用教科书知识生成，与老师课件不符
- 解决：优先提取真实资料内容，只有资料严重不足时才补充领域知识

## 沟通类

**1. 没有及时报告进度**

- 解决：每完成一个阶段就汇报

**2. 过度承诺**

- 解决：保守承诺，超预期交付

**3. 没有先确认需求就开始做**

- 解决：先问清楚需求再动手

**4. 反馈不具体**

- 解决：交付时列出「请重点检查：公式清晰度、答案交互、打印效果」

## 效率技巧（通用）

1. **先计划后执行** — 避免方向错误
2. **文件越少越好** — 一站式优于碎片化
3. **CSS 样式先行** — 避免类名不匹配
4. **JSON 存 LaTeX** — 彻底避免转义问题
5. **局部替换优于全量** — 用深度计数器定位
6. **Windows 脚本禁 emoji** — 避免控制台编码报错
7. **Agent 输出必须落盘** — 指令中写明要写入的文件路径

视觉分析专用的效率技巧在 [`vision-workflow.md`](vision-workflow.md)。
